# 실사용 파일럿(Harvest Frontier) 피드백 기반 로드맵

작성일: 2026-08-21. 출처: Harvest Frontier(실제 3D 팜 게임, 런타임 GLB 8종·텍스처 6종 운용) 세션이
24시간 실사용 후 보낸 평가·제안 전문. 모든 항목은 HF가 "실제로 소비할 것"이라 확인한 실수요만
담는다 — 가설 수요 없음.

## HF의 핵심 진단 (원문 요지)

> "현재 Clunk의 확실한 가치는 '공증'(해시·재검사 manifest 교환)이다. 그러나 지난 24시간 HF가
> 만든 품질 상승의 거의 전부가 Clunk의 시야 밖이었다 — 실제로 싸운 문제(밉체인 판독성,
> 이중 감쇠, 드로우콜 예산, 렌더러 밝기 편차)는 전부 씬·런타임 레벨이라 정적 GLB 단품 검사가
> 원리적으로 잡을 수 없다. 게임 제작 도구로 도약하려면 정적 GLB → 씬·텍스처·캡처·시계열로
> 시야를 넓혀야 한다."

## 반영 완료 (2026-08-21 당일 구현)

| 항목 | HF 요구 | 구현 |
| --- | --- | --- |
| 웹 커스텀 프로파일 | "프로파일 없는 웹 검사기는 데모지 도구가 아니다" | 검사기에 프로파일 JSON 업로드 + 커스텀 칩. 로컬 검사 전용(저장·크레딧 없음)으로 정직하게 경계 표시. HF 트랙터 100/100 실증 |
| 워치 모드 + ref | "검사가 커밋에 자동으로 묶여 남지 않는 것"이 최대 아쉬움 | `clunk watch <경로…> --profile-file … --manifest … --ref <커밋>`: 변경 감지→자동 재검사→ref 스탬프 manifest 갱신. HF 런타임 8종 실증 |

| 점수-기준 병기 | "점수가 표시되는 모든 곳에 어느 프로파일 기준인지" | 검사기 룰셋 표기 + 대시보드 이력 '기준' 칩 |

## P0 — 다음 구현 대상 (HF가 즉시 파이프라인에 물리겠다고 확약)

1. **텍스처 세트 검사** (별도 입력 타입: 이미지 폴더/manifest — GLB에 욱여넣지 않음)
   - 우선순위(HF 지정): ① 밉체인 판독성 예측(주파수 스펙트럼 × 텍셀 밀도 → "X미터에서 디테일 소멸" — HF가 M65에서 수동 진단한 4.2m/타일=4.1mm 텍셀→15m 밉2-3 평탄화의 자동화) ② 타일 심리스(경계 픽셀 연속성) ③ 밉 포함 GPU 메모리 합산 예산(HF는 19.98/40MB를 수동 계산 중) + sRGB/linear 플래그.
   - **①②③ 전부 v0.2 구현·HF 지상 진실 검증 완료(2026-08-21)**: `scripts/texture-audit.mjs`
     (의존성 0 — PNG 디코더 자체 구현, sRGB→linear, 밉체인, 보존율+★처방 필드).
     캘리브레이션 기록: HF 제안 σ_floor 노브는 실데이터로 **반증**(절대 σ 순서가 예측과
     역순) → 후보 4종 실측 → **잔여 입자성 grad/σ 노브**(비율 C 대역에서 >0.40이면
     wash 강등)로 확정, **8/8 전 케이스가 HF 마일스톤 감사 기록(육안 지상 진실)과 정합**
     (grass3.4→D·grass11→A·dirt→C·soil→D/D·wood→C·plaster→C·roof→A). 1점 캘리브레이션
     한계는 문서화, chroma 노브는 예비. ② 타일 심리스: 랩 경계/내부 스텝 비율 — 6종 중
     5종 SEAMLESS(0.89~1.18), **roof-tiles VISIBLE-SEAM(V 5.78) 실결함 검출**. ③ GPU
     메모리(밉 포함 RGBA8): 합산 20.00MB/40MB — HF 수동 계산 19.98MB와 일치(교차 검증).
     설정 예: `examples/texture-audit/harvest-frontier.textures.json`.
2. **씬 레벨 검사** (glTF 씬 or 런타임 텔레메트리 JSON 입력)
   - 서브시스템별 드로우콜/삼각형, 인스턴싱 커버리지(반복 메시 중 미인스턴스 비율), 머티리얼 수, 오버드로우 추정. HF는 매 마일스톤 수동 계산.

## P1

- **캡처 시각 회귀**: 스크린샷 지각 diff + 변화 영역 주석. 렌더러 패리티(WebGPU vs WebGL2 밝기/색 편차 정량화) 포함. HF "3초 상용 판정" 루프의 자동화.
- **프로파일 계약 확장**: named-node 계약(pivot/socket/collider), 축 규약(진행축 -X 등), LOD 쌍 검증(far<near tri/bytes, 비율 범위, 예산 쌍). HF의 수제 validate-*.ts를 프로파일 데이터로 이관하는 경로.
- **검사-ref 서버 연동**: inspection 레코드에 자유 ref(커밋) 필드. ※ D1 스키마 변경 필요 —
  ensureSchema ALTER 함정(docs/design/server-reinspection.ko.md) 때문에 **제출(9/17) 전 머지 금지**,
  watch manifest의 ref가 그때까지의 대체 경로.
- **계보(lineage) 뷰**: 해시가 바뀌어도 같은 자산명(tractor.compact.m1)의 시간축으로 이력을 묶기.
  현 수동 manifest 왕복의 제품화. (서버 스키마 필요 — 위와 동일한 프리즈 제약)

## P2

- **perf 시계열**: HF p95 통제 프로토콜(N=7 중앙값/IQR) 산출 JSON을 커밋별 적재·추세화.
- **provenance 체인 검증**: source-manifest(생성 원본 해시) → 파생본 해시 체인 자동 감사. 공증 역할의 자연 확장.

## 병행 트랙 — 생성 파이프라인 (마스터 지시, 2026-08-21 1차 구현)

생성→검수→판정→Passport를 한 파이프라인으로 닫는 트랙. img2threejs(Apache-2.0) 규율의
에이전트 절차 생성 + `scripts/threejs-to-glb.mjs` GLB 추출 레일 + 기존 게이트로 구성.
1차 실증(풍차 데모: 408 tri·5 mat·100/100 READY·Passport 발급)은
[generate-pipeline.ko.md](generate-pipeline.ko.md), 경쟁 구도는
[benchmark-meshy.ko.md](benchmark-meshy.ko.md) 참조. 후속: 텍스처 포함 생성물(P0 텍스처
검사와 합류), Meshy MCP ↔ Clunk MCP 연계 데모(계획).

## 사업 관점 메모

이 문서 전체가 "실제 게임 제작팀이 검증한 수요"의 1차 증거다. 신청서·피칭의 로드맵 항목은
여기서만 가져오고, 구현 전 항목은 반드시 "계획"으로 표기한다(날조 금지 원칙).
