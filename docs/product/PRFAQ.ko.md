## 보도자료 (Press Release — 출시 시점 가정)

### 아르테미스, 증거로 파는 게임 에셋 파운드리 'Clunk' 정식 출시

**— 만들고, 증명하고, 판매합니다. 에셋의 게임 투입 가능성을 바이트 단위 증거로 봉인하는 첫 마켓.**

인천, 2026년 ○월 ○일 — 아르테미스(대표 박준성)가 게임 에셋의 생성·검사·판매·에이전트 연동을 하나의 증거 체인으로 묶은 파운드리 **Clunk**를 정식 출시했다.

게임 개발자는 지금까지 에셋을 '스크린샷을 보고' 샀다. 사 놓고 나서야 트라이앵글 예산 초과, 깨진 스케일, 텍스처 메모리 폭탄을 발견했다. AI 생성 도구의 폭발로 에셋의 공급은 무한해졌지만, **"이 파일이 실제 게임에서 돌아간다"는 증명은 어디서도 팔지 않았다.**

Clunk의 모든 판매 에셋은 자체 GLB/glTF 바이트 파서의 17개 정책 룰 검사를 통과하고, 트라이앵글·드로우콜·해시·경고까지 실측값 그대로 상품 페이지에 공개된다. 생성 이력(프롬프트·모델·해시)은 provenance로, 검사→수리→재검사는 결정론적 Passport로 봉인된다. 파일 저장·출처·라이선스·정적 검사·런타임 확인·플레이어 화면·사람 승인 — **7개 게이트를 전부 통과한 에셋만 게시된다.**

Clunk는 출시 전부터 실제 게임 두 프로젝트의 납품 라인으로 검증됐다. 실게임 납품 3D 에셋은 재검사 100/100을 기록했고, 2D/VFX 22종은 소비자 측 무결성 감사 24/24를 통과했다. 이 과정에서 축적된 통합 규칙은 Clunk의 에이전트 지식 원장이 되었다.

결제는 크레딧 하나로 통일된다(1크레딧 = 100원). 생성도, 검사도, 에셋 구매도 같은 크레딧을 쓴다. Claude Code·Codex·Cursor 등 에이전트에는 MCP 7툴·CLI·VS Code 확장이 같은 계약으로 붙는다 — 에이전트가 직접 에셋을 만들고, 검사하고, 사 오는 게임 제작 파이프라인이 열린다.

"스크린샷은 거짓말을 해도 바이트는 못 합니다. 저희는 예쁜 렌더가 아니라 검사 결과를 팝니다." — 박준성, 아르테미스 대표. *(가상 인용)*

"산 에셋을 엔진에 넣고 기도하던 시간이 사라졌어요. 상품 페이지의 드로우콜 수치가 곧 계약서니까요." — 인디 개발자 ○○○. *(가상 인용)*

Clunk는 https://clunk.artemis-clunk.workers.dev 에서 시작할 수 있다.

## 외부 FAQ (고객)

**Q. 다른 AI 에셋 생성 서비스와 뭐가 다른가요?**
생성 서비스는 파일을 만들어 주고 끝납니다. Clunk는 그 파일이 **게임에 들어갈 수 있는지를 검사하고 증거를 남기는 것**이 제품입니다. 생성은 저희 것(2D luna 엔진, 3D 팩토리)을 쓰든 외부 파일을 가져오든 상관없습니다 — 검사·수리·Passport·마켓 게이트는 어떤 파일에나 동일하게 적용됩니다.

**Q. "게임 레디"를 어떻게 믿죠?**
안 믿으셔도 됩니다 — 그래서 증거를 드립니다. 모든 상품 페이지에 실측 트라이앵글·드로우콜·바이트·SHA-256·검사 finding(경고 포함)이 그대로 공개됩니다. 점수는 17개 룰 기반 Game-Ready 스코어(임계 90)이고, 구조 점수·런타임 확인·플레이어 화면·사람 승인은 서로 절대 승격되지 않는 독립 상태입니다. 경고 하나까지 숨기지 않습니다.

**Q. 가격은요?**
모든 사용이 크레딧입니다. 1크레딧 = 100원 고정 환산이고, 에셋 가격은 상품 페이지에 원화·크레딧으로 표시됩니다. 크레딧 팩 가격은 판매 개시 시점에 공지됩니다.

**Q. 환불이 되나요?**
디지털 콘텐츠 특성상 **다운로드 권한이 부여되는 즉시 청약철회가 제한**되며, 결제 전에 이 내용에 명시적으로 동의해야만 결제가 시작됩니다(전자상거래법 제17조 2항 5호 고지·동의 구조). 상세 기준은 취소·환불정책 페이지에 있습니다.

**Q. 라이선스는요?**
게시 게이트에 라이선스 선언이 포함됩니다 — 라이선스가 확인되지 않은 파일은 게시 자체가 안 됩니다. 구매 시 파일·해시·라이선스가 상품 단위로 따라갑니다.

**Q. 어떤 에이전트에 연결되나요?**
MCP를 지원하는 모든 클라이언트(Claude Code, Codex CLI, Cursor, VS Code 등). HTTP와 로컬 stdio가 같은 7개 툴 계약을 씁니다. CLI와 VS Code 확장, Codex 플러그인도 저장소에 포함돼 있습니다.

**Q. 지금 바로 살 수 있나요?**
통신판매업 신고 완료 전까지는 **모든 판매가 잠금 상태**입니다. 카탈로그·검사·에이전트 연결은 열려 있고, 판매 개시는 사이트에 고지됩니다.

## 내부 FAQ (하드 질문)

**Q. meshy 같은 대형 생성 서비스가 검증 기능을 붙이면 끝나는 것 아닌가?**
그들의 제품은 생성량·렌더 품질로 팔리고, 검증은 그들의 생성물 약점을 드러내는 기능이라 인센티브가 역방향이다. Clunk는 반대로 **검증이 본체라 생성 모델 종속이 없다** — 외부 파일도 같은 게이트를 통과시키므로, 생성 도구가 늘어날수록 검사 수요는 커진다. 또한 4-상태 분리·Passport·exit code 계약 같은 '증거 문화'는 기능 복제가 아니라 운영 원칙의 문제다.

**Q. 마켓 콜드스타트(상품 없음·구매자 없음)는?**
1st-party 인벤토리로 시작한다 — wave1 19상품은 실게임 납품 라인에서 나온 실측 검증품이다. 구매자 획득은 마켓 단독이 아니라 검사·에이전트 축의 사용자(개발자)가 크레딧을 이미 들고 있는 구조로 푼다. 외부 판매자 온보딩은 정산 인프라가 갖춰지는 v2로 미룬다(Non-Goal 명시).

**Q. AI 생성물의 저작권 리스크는?**
v1 인벤토리는 전부 자체 Three.js 팩토리(절차 생성 코드)와 자체 프롬프트 luna 생성물 — 제3자 IP 학습 재현 리스크가 구조적으로 낮은 라인이다. 그래서 라이선스 선언을 게시 게이트에 하드 조건으로 박았고, 외부 크리에이터를 받지 않는 것도 같은 이유다. provenance(프롬프트·모델·해시)가 분쟁 시 방어 기록이 된다.

**Q. 1인 운영이 병목 아닌가? 특히 사람 승인(humanDecision) 게이트.**
맞다, 그래서 두 가지로 설계했다: ① 사람 승인 전 단계(구조·런타임·화면)는 전부 자동화·배치화되어 사람은 최종 판정만 한다 ② 에이전트 오케스트레이션이 제작·검사·감사를 병렬화한 실적이 이미 있다(HF/FF 납품을 1인+에이전트로 수행). 그래도 남는 리스크는 게시 처리량이며, 이는 성공했을 때의 문제다.

**Q. 크레딧 경제를 쓰는 이유는? 그냥 개당 결제가 단순하지 않나?**
세 축(생성·검사·구매)의 과금을 하나의 원장으로 통일하면 ① 소액 다빈도 사용(검사 1회 등)의 결제 마찰이 사라지고 ② 재충전율이라는 단일 리텐션 지표가 생기며 ③ 구독(크레딧 번들)으로 자연 확장된다. 원장은 예약→확정→환불 3단계 idempotent 연산으로 이미 구현·검증됐다.

**Q. 왜 아직 매출이 0인가?**
법정 요건(통신판매업 신고) 미완 — 의도된 잠금이다. 잠금 상태에서 전 레일(결제 제외)을 완성·QA하는 것이 현 단계의 정의된 목표이며, 이 문서의 P0 목록이 해제 조건이다.

**Q. 실패 판정은 언제 하나?**
출시 +30일에 PRD 4.2 지표로 평가한다. 활성화 40% 미달이면 온보딩(첫 검사 경험)을, 첫 결제 5% 미달이면 가격·팩 구성을, 재충전 20% 미달이면 크레딧 소모처(생성·검사 가치)를 재설계한다. 지표는 전부 D1 원장 쿼리로 검증 가능해 해석 논쟁의 여지가 없다.
