## 1. 배경 및 목적 (Why)

### 1.1 문제

게임 에셋 시장에는 세 개의 신뢰 단절이 있다.

1. **"게임에 넣어보기 전엔 모른다."** 마켓에서 산 에셋이 트라이앵글 예산 초과, 머티리얼 중복, 깨진 스케일, 텍스처 메모리 폭탄으로 실제 게임에서 못 쓰는 경우가 흔하다. 스토어 스크린샷은 렌더 품질을 보여줄 뿐, 엔진 투입 가능성을 증명하지 않는다.
2. **AI 생성 에셋의 품질 불신.** 생성 도구는 폭발적으로 늘었지만 "이 파일이 실제로 게임 레디인가"를 검증해 주는 곳이 없다. 생성물은 많고 증거는 없다.
3. **에이전트 시대의 파이프라인 단절.** 게임 제작이 Claude Code·Codex·Cursor 같은 에이전트로 넘어가고 있는데, 에셋의 생성→검사→수정→투입 루프는 여전히 사람이 손으로 잇는다.

### 1.2 Clunk의 답

**만들고, 증명하고, 판매한다.** Clunk는 에셋의 생애 전체를 하나의 증거 체인으로 묶는 파운드리다.

- **제작·판매**: 프롬프트→2D(luna 엔진), Three.js 팩토리→3D GLB를 실제 바이트로 생성하고, 게시 게이트를 통과한 것만 마켓에 올린다.
- **검사·수정**: GLB/glTF 바이트 파서가 [실측] 17개 정책 룰로 검사하고 Game-Ready 점수(임계 90)를 산출, 허용 목록 수리 연산 4종으로 안전하게 수정하며, 전 과정을 결정론적 digest의 Passport로 봉인한다.
- **게임 제작 에이전트**: 같은 계약을 [실측] MCP 7툴(HTTP·stdio 동일)·CLI·VS Code 확장으로 노출해 에이전트가 직접 부른다.

차별점은 기능 목록이 아니라 **문화**다: 구조 점수·런타임 캡처·플레이어 화면·사람 승인을 절대 섞지 않는 4-상태 분리(structural / visualRuntime / playerFacing / humanDecision), 그리고 "지어낸 지표 0" 원칙. 경쟁 생성 도구(meshy 등)가 "만들기"에서 멈출 때 Clunk는 "증명"을 판다.

### 1.3 비즈니스 목표

- 아르테미스의 첫 수익 제품: **크레딧 경제**(1크레딧 = ₩100 [실측: 코드 상수]) 기반 SaaS. 생성·검사·구매가 전부 크레딧으로 결제된다.
- 2026-09-17 모두의 창업 2차(예비창업자) 신청의 핵심 아이템 — 이 PRD·PRFAQ가 그 근거 문서다.
- 통신판매업 신고 완료 즉시 실판매 개시(현재는 전 레일 완성 + 판매 잠금 상태 유지).

### 1.4 실증 (이미 확보한 증거)

- [실측] 실게임 Harvest Frontier에 3D 에셋 납품 라인 가동 — 납품 GLB 재검사 100/100, 하드 블로커 0.
- [실측] FORGE FRONT에 2D/VFX 납품 — 소비자 감사 24/24 무결성 PASS, 스프라이트 게이트 22/22.
- [실측] 실게임 피드백으로 만든 에이전트 지식 원장 R-001~R-010 (에셋 통합 규칙).
- [실측] wave1 마켓 인벤토리 19상품·94파일 패키징 완료(게시 대기).

## 2. 사용자 시나리오 (Who & User Story)

### 페르소나 A — 인디 게임 개발자 "지호" (구매·검사자)

웹/모바일 게임을 혼자 만든다. 에셋을 살 돈은 있지만 산 에셋이 게임에서 터지는 경험을 반복했다.

- 지호는 **마켓의 에셋 상세에서 실측 트라이앵글·드로우콜·해시·검사 결과를 먼저 보고** 구매를 결정한다. 스크린샷이 아니라 증거로 산다.
- 지호는 **크레딧으로 에셋을 구매하고 즉시 GLB를 다운로드**한다. 결제 확인 즉시 entitlement가 부여된다.
- 지호는 **외부에서 받은 에셋도 업로드해 17룰 검사와 Game-Ready 점수**를 받고, 모바일 타깃 프로파일로 수정 방향을 잡는다.
- (예외) 지호가 잔액보다 비싼 에셋을 사려 하면 **부족분이 명시된 402 응답**을 받고 충전 페이지로 안내된다. 결제가 중복 클릭되어도 **idempotency 키로 이중 차감이 발생하지 않는다.**

### 페르소나 B — 에셋 크리에이터 "마스터" (제작·판매자, 현재는 운영자 겸)

- 마스터는 Studio에서 **프롬프트로 2D를, 팩토리 레시피로 3D를 생성**하고, 생성물의 프롬프트·모델·해시가 provenance로 자동 기록된다.
- 마스터는 **게시 게이트 7조건(파일 저장·provenance·라이선스·정적 PASS·런타임 PASS·플레이어 화면 PASS·사람 승인)을 전부 통과한 listing만 PUBLISHED**로 만들 수 있다 — 조건 미달이면 API가 409로 거부한다.
- (예외) 스토리지(R2)가 없는 환경에서는 생성 결과가 **LOCAL_PREVIEW_ONLY로 정직하게 표시**되고 게시가 차단된다.

### 페르소나 C — 에이전트 운영 개발자 "연서" (자동화)

Claude Code로 게임을 만드는 개발자. 에셋 파이프라인을 에이전트에게 맡기고 싶다.

- 연서는 **MCP 설정 한 블록으로 Clunk를 연결**하고, 에이전트가 `clunk_asset_author`(생성)→`clunk_asset_inspect`(검사)→`clunk_optimize`(수리)→`clunk_sprite_sheet_review`(시트 검증)를 직접 호출하게 한다.
- 연서의 에이전트는 **HTTP와 로컬 stdio에서 같은 계약**을 쓰므로 CI에서도 로컬에서도 동일하게 동작한다.
- (예외) HTTP 표면은 로컬 경로를 절대 dereference하지 않는다 — 원격에서 파일 재해시가 필요한 요청은 **로컬 CLI로 경계가 명시**된다.
- 실증: 이 시나리오는 가상이 아니라 **HF·FF 두 실게임 세션과의 협업에서 이미 검증**되었다(주문→납품→감사→지식 원장 루프).

### 페르소나 D — QA 운영자 (출시 전 현재의 마스터)

- QA 운영자는 **QA 키로 로그인**해(OAuth 등록 전) 데모 크레딧을 지급받고, **실제 결제 없이 구매→차감→다운로드 전 과정을 검증**한다. 실결제 provider가 설정되는 순간 데모 지급 경로는 도달 불가능해진다.

### 3.5 대표 수용 기준 (Acceptance Criteria 발췌)

- **크레딧 구매**: Given 잔액 50, 상품 19크레딧 / When 구매 2회 연속 클릭(같은 idempotency 키) / Then 차감은 정확히 19, 주문 1건 PAID, entitlement 1건, 잔액 31.
- **잔액 부족**: Given 잔액 10, 상품 19크레딧 / When 구매 / Then 402 + `INSUFFICIENT_CREDITS` + 필요 크레딧 명시, 주문·entitlement 미생성.
- **게시 게이트**: Given humanDecision=NOT_EVALUATED인 에셋 / When status=PUBLISHED로 POST / Then 409 + 게이트별 사유 목록.
- **데모 지급 차단**: Given Stripe 키 설정됨 / When 팩 구매 / Then 데모 분기 도달 불가, 실제 Stripe 세션 생성.
- **QA 로그인**: Given `CLUNK_QA_LOGIN_KEY` 미설정 배포 / When GET /api/auth/qa / Then `enabled:false`, POST는 404.

## 4. 성공 지표 (Metrics)

측정은 전부 D1 원장(주문·크레딧 연산·entitlement 테이블) 쿼리로 가능하다 — 별도 분석 도구 없이 검증 가능한 지표만 설정한다.

### 4.1 현재 기준선 [실측]

| 지표 | 값 |
|---|---|
| 게시 가능 인벤토리 | 19상품 94파일 (wave1) |
| 실게임 납품 검증 | HF 재검사 100/100 · FF 감사 24/24 무결성 |
| 정책 룰 / MCP 툴 | 17룰 · 7툴(HTTP=stdio) |
| 유료 사용자·매출 | 0 (판매 잠금 — 정직 고지) |

### 4.2 출시 후 목표 [가설 — 출시 +30일 평가]

| 지표 | 성공 기준 | 스트레치 | 측정 방법 |
|---|---|---|---|
| 가입→첫 검사/생성 실행 (활성화) | ≥ 40% | 60% | users ↔ analysis_runs/generation_jobs 조인, 가입 후 72h 윈도 |
| 첫 크레딧 결제 전환 | ≥ 5% | 10% | credit_orders PAID / 가입자 |
| 에셋 구매 전환(크레딧 보유자 중) | ≥ 25% | 40% | marketplace_orders PAID / 크레딧 보유 워크스페이스 |
| 월 크레딧 재충전율 | ≥ 20% | 35% | 2회차 credit_orders / 1회차 구매자 |
| 구매 분쟁·환불율 | < 2% | <1% | REFUNDED / PAID |
| MCP 주간 활성 연결 | ≥ 10 워크스페이스 | 30 | api_keys 사용 로그 주간 유니크 |
| 검사 API 오류율 | < 1% | <0.5% | 5xx / 전체 (레이트리밋 제외) |

### 4.3 선행 게이트 지표 (출시 전, 지금 측정)

- QA 시나리오 통과: 로그인→데모 지급→구매→차감→다운로드 전 구간 무결점 (마스터 직접 검증 예정)
- 게시 게이트 통과율: wave1 19/19 PUBLISHED (R2 활성화 후)
- 라이브 시각 검증: 데스크톱+모바일 풀페이지 렌더 무결(2026-08-31 사고 재발 방지 절차 상시화)

## 5. 우선순위 및 제약 조건

### 5.1 Must-have (P0) — 이것 없이는 출시 불가

### 5.4 Non-Goals (v1에서 명시적으로 안 하는 것)

- **범용 AI 아트 생성기 경쟁** — 생성은 수단이고 제품은 '증명'이다. 생성 모델 자체 개발 없음.
- **커뮤니티/소셜 기능** — 리뷰·팔로우·피드 없음. 콜드스타트에 증거로 승부.
- **실시간 협업 편집** — 협업은 스레드·evidence 교환으로 한정.
- **모바일 네이티브 앱** — 반응형 웹으로 충분.

### 5.5 제약 조건

- **법률**: 통신판매업 신고 전 실판매·실결제 절대 금지(현 판매락의 근거). 크레딧·디지털 콘텐츠 청약철회 제한은 고지·동의 선행 구조로 이미 구현.
- **인프라**: R2 미활성(계정 동의 필요), Workers 무료 플랜 한도, D1 단일 리전.
- **운영**: 1인 운영(마스터) + AI 오케스트레이션 — 사람 검수(humanDecision)가 병목이 될 수 있어 게시 파이프라인은 배치 검수로 설계.
- **일정**: 모두의 창업 2차 마감 **2026-09-17 16:00** — 신청서에 라이브 제품+이 문서 첨부 가능해야 함.
- **원칙**: 지어낸 지표·가짜 상태 금지. 미완성은 UNAVAILABLE/대기로 정직하게 표시한다.
