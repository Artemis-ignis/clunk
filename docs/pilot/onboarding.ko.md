# 파일럿 팀 온보딩

> 이 문서의 사실 근거: 저장소 `README.md`(실행 방법·저장/인증/결제 경계·정직한 제한), `docs/application/form-answers.ko.md` Q3-1 마지막 문단(원본 브라우저 처리·서버 메타데이터만), `db/schema.ts`·`app/api/`(실제 저장 필드), `public/llms.txt`(판정 3단계·규칙 세트·허용 목록 작업).

첫 세션은 45~60분입니다. 목표는 기능 설명이 아니라 **그 팀의 실제 에셋 한 개가 검사 → 정리 → 재검사 → Passport까지 한 바퀴 도는 것**입니다. 한 바퀴를 못 돌면 이후 측정도 인터뷰도 의미가 없습니다.

## 0. 세션 방식 정하기 (진행자가 미리 선택)

| | A안 · 초대 세션 | B안 · 로컬 실행 |
| --- | --- | --- |
| 방식 | 진행자 화면에서 함께 진행하거나, 진행자가 띄운 세션에 참여 | 팀이 자기 PC에 저장소를 받아 직접 실행 |
| 장점 | 설치 실패가 없고 첫 성공까지 빠름 | 반복 사용이 가능해 실제 측정이 나옴 |
| 단점 | 반복 사용을 관찰하기 어려움 | Node·npm 설치 단계에서 이탈 가능 |
| 권장 | 첫 세션 | 첫 세션 이후 2~4주 반복 사용 |

권장 조합: **첫 세션은 A안, 이후 B안으로 넘기기.** 공개 URL이 없는 비공개 파일럿이므로 "링크 하나 드릴게요"는 불가능합니다. 이 사실을 첫 연락에서 미리 알려야 세션 당일에 당황하지 않습니다.

## 1. 사전 준비물 (팀에게 미리 보낼 것)

**에셋**

- 실제 작업 중인 GLB 또는 GLTF **3~5개**. 잘 도는 것 2개, 문제가 있었던 것 1~2개를 섞어주시면 가장 좋습니다.
- 출처가 섞이면 좋습니다: 외주 납품본, 에셋 마켓 구매본, AI 생성물, 직접 만든 것.
- `.gltf`는 외부 리소스(`.bin`, 텍스처)를 참조하므로 **폴더째** 준비하세요. 파일 하나만 있으면 리소스 누락으로 판정이 막힙니다(`SEC-MISSING-RESOURCE`).
- 원격 URL을 참조하는 glTF는 `SEC-REMOTE-RESOURCE`로 걸립니다. 정상 동작이며 팀에게 미리 알려주세요.
- 지나치게 큰 파일은 첫 세션에 적합하지 않습니다. 대용량은 2회차에 시도하세요.

**환경**

- 최신 Chrome 또는 Edge.
- (B안) Windows PowerShell, Node.js와 npm. 실행은 `npm.cmd install` → `npm.cmd run generate:samples` → `npm.cmd run dev` → `http://localhost:3000`.
- ChatGPT 계정. `/app`, `/dashboard`, `/settings`와 저장 API는 모든 환경에서 SIWC(Sign in with ChatGPT) 인증을 요구하고, 인증이 없으면 로그인 화면으로 보냅니다.

**확인해 둘 것**

- 그 에셋을 외부 도구로 열어봐도 되는지 팀·클라이언트 규정. NDA 대상이면 대체 파일로 진행하세요.
- 파일명이 미공개 프로젝트명이나 클라이언트명을 드러내는지. 드러난다면 파일명을 바꿔서 가져오세요(뒤의 "저장되는 것" 참고).

## 2. 첫 세션 진행 순서

**(1) 로그인 · 5분**
로그인 화면에서 ChatGPT로 인증합니다. 계정마다 워크스페이스가 분리됩니다. 여기서 미리 말할 것: 비밀번호를 보관하지 않는다는 점, 원본 에셋이 업로드되지 않는다는 점, 화면의 크레딧과 플랜은 `DEMO MODE · 실제 결제 아님`이라는 점.

**(2) 샘플 1회 · 5분**
`샘플로 시작` 버튼으로 문제 있는 샘플 GLB를 한 번 돌립니다. 화면 구조(관측 메트릭 / 정책 finding / 3D 미리보기 / 점수)를 익히는 용도입니다.
말해 둘 것: **샘플 실행은 워크스페이스 지표와 크레딧에서 의도적으로 제외됩니다.** 검사 이력에도 남지 않습니다. 이건 버그가 아니라 설계입니다.

**(3) 본인 에셋 검사 · 15분**
팀이 직접 파일을 놓고 프로파일(web / mobile / pc)을 고릅니다. 프로파일별 기본 예산은 이렇습니다.

| 프로파일 | 삼각형 | 머티리얼 | 텍스처 메모리 | 최대 텍스처 변 |
| --- | ---: | ---: | ---: | ---: |
| web | 100,000 | 12 | 128MB | 4096 |
| mobile | 25,000 | 6 | 64MB | 2048 |
| pc | 250,000 | 24 | 512MB | 8192 |

여기서 진행자가 할 일은 설명이 아니라 **관찰**입니다. 어떤 프로파일을 고르는지, finding 중 무엇을 먼저 읽는지, 어디서 "이건 우리 기준이랑 다른데요"라고 말하는지 그대로 적어두세요. 이 메모가 인터뷰의 절반을 만듭니다.

판정은 세 가지입니다.

- `준비 완료` — 차단 finding이 없고 선언된 정책을 충족
- `조건부 준비` — 차단 요소는 없지만 무손실 정리로는 해결되지 않는 경고가 남음
- `차단됨` — ERROR 또는 CRITICAL finding이 남아 있음

**중요:** `조건부 준비`는 "대충 괜찮음"이 아니라 "남은 경고를 사람이 판단해야 함"입니다. 실제로 저희 참조 게임의 런타임 GLB 8개를 `pc` 프로파일로 검사했을 때 8개 모두 `READY=false`였습니다. 범용 정책이 프로젝트 자체 기준을 대체하지 못한다는 뜻이고, 이 한계를 첫 세션에서 먼저 말해야 신뢰를 잃지 않습니다.

**(4) 안전 최적화 · 10분**
허용 목록에 있는 작업만 적용됩니다: `prune-empty-nodes`(빈 노드 제거), `dedupe-materials`(중복 머티리얼 정리), `clean-metadata`(지정한 비런타임 메타데이터 정리), `repack`(별도 파일 재패킹). 이 중 `prune-empty-nodes`·`dedupe-materials`·`repack`은 무손실이고, `clean-metadata`만 메타데이터 한정입니다.
원본은 절대 덮어쓰지 않고 항상 새 파일이 나옵니다. 결과는 "최적화 완료" 문구가 아니라 **새 파일을 처음부터 다시 파싱한 검사 결과**로 보여집니다.
v1이 하지 않는 것도 이 자리에서 말합니다: mesh 단순화, 텍스처 재인코딩, Draco/Meshopt, 양자화, 애니메이션·스킨 변경, 알 수 없는 확장 변경.

**(5) Passport와 다운로드 · 5분**
Passport에는 입력·출력 SHA-256, 규칙 세트 ID와 버전, 적용한 작업 목록, 전후 메트릭·점수, 전후 검사 리포트 digest가 들어갑니다. 최적화된 GLB와 Passport JSON을 실제로 내려받게 하세요. 내려받은 파일을 팀이 자기 엔진에 넣어보는 것까지가 진짜 검증입니다.

**(6) 대시보드 확인 · 5분**
`/dashboard`에서 저장된 검사 이력, 크레딧 원장, Passport를 봅니다. 크레딧은 초기 25로 시작하고 검사 1회 -1, 최적화 1회 -1입니다. 실패하거나 거부된 요청은 차감도 기록도 되지 않고, 같은 요청이 중복 도착해도 이중 차감되지 않습니다. 부족하면 화면의 데모 업그레이드(+100, 1회)를 안내하세요. **실제 결제가 아닙니다.**

**(7) 마무리 · 5분**
다음 2~4주 동안 실제 작업에서 쓰실 수 있게 접속 방법을 정리해 드리고, 인터뷰 일정을 이 자리에서 잡습니다. "나중에 연락드릴게요"로 끝나면 대부분 인터뷰가 성사되지 않습니다.

## 3. 에셋 보안·개인정보 안내 (그대로 읽어도 되는 문구)

> 원본 에셋 파일은 브라우저 안에서 처리하고 서버로 자동 업로드하지 않습니다. 서버에는 검사 이력·해시·점수 같은 메타데이터만 저장합니다.

이 문구는 신청서 Q3-1의 검증된 표현과 동일합니다. 여기서 한 발 더 나가 "보안이 강화됩니다"라고 말하지 마세요. 보안 효과 자체를 측정한 단계가 아닙니다.

**서버(D1)에 실제로 저장되는 것**

- 에셋: 파일명, 포맷(glb/gltf), 바이트 길이, SHA-256
- 검사: 입력 해시, 프로파일 ID, 규칙 세트 ID, 상태, 점수, 차단 finding 수, 전체 finding 수, 검사 리포트 JSON, 생성 시각
- 최적화: 소스 해시, 출력 해시, 적용 작업 목록, 상태, 생성 시각
- Passport: 소스/출력 해시와 Passport JSON
- 계정·워크스페이스·구독 상태, 크레딧 원장

**저장되지 않는 것**

- 원본 바이트, 최적화 출력 바이트, 텍스처 이미지
- 3D 미리보기 화면

**팀에게 반드시 알릴 두 가지**

1. **파일명은 그대로 저장됩니다.** 파일명이 미공개 프로젝트명·클라이언트명을 담고 있으면 검사 전에 바꿔서 넣으시라고 안내하세요.
2. **검사 리포트 JSON이 저장됩니다.** 여기에는 삼각형 수, 머티리얼 수, 텍스처 해상도, 노드 경로 같은 구조 정보가 들어갑니다. 파일 자체는 없지만 에셋의 형태는 어느 정도 드러납니다.

**계정과 워크스페이스**

워크스페이스는 로그인한 계정에서 파생되므로 **계정 하나에 워크스페이스 하나**입니다. 팀원 여러 명이 각자 로그인하면 이력이 각자 워크스페이스로 나뉩니다. 팀 공유 워크스페이스는 아직 없습니다(로드맵). 파일럿에서 한 팀의 사용량을 한 덩어리로 보려면 어떤 계정으로 쓰실지 첫 세션에서 정해두세요.

**인터뷰·기록**

- 세션 중 진행자가 메모합니다. 녹음·녹화는 사전 동의 없이 하지 않습니다.
- 팀 이름과 사례를 외부에 공개할 때는 매번 별도 동의를 받습니다. 동의 없이는 익명·집계로만 씁니다.
- 저장된 이력 삭제를 요청하시면 워크스페이스 단위로 처리합니다. 요청 경로는 아래 연락처입니다.

## 4. 문제가 생겼을 때

**연락 경로:** [연락처] · 응답 목표 영업일 1일 이내

**보내주실 것**

1. 무엇을 하려다 무엇이 나왔는지 한 줄
2. 재현 순서 (파일 놓기 → 프로파일 선택 → 최적화 클릭 …)
3. 파일 특성: 포맷, 대략적인 크기, 삼각형 수, 외부 리소스 유무
4. 화면 스크린샷 또는 브라우저 콘솔 오류
5. 필요하면 검사 리포트 JSON 또는 Passport JSON

**보내지 않으셔도 되는 것: 원본 에셋 파일.** 요청하지 않습니다. 재현이 꼭 필요하면 그때 별도로 상의합니다.

**자주 나오는 상황**

| 증상 | 원인 | 대응 |
| --- | --- | --- |
| 로그인 화면으로 계속 돌아감 | SIWC 인증 없음 | ChatGPT 로그인 후 재시도 |
| `SEC-MISSING-RESOURCE` | `.gltf`의 `.bin`·텍스처 누락 | 폴더째 다시 시도 |
| `SEC-REMOTE-RESOURCE` | 원격 URL 참조 | 정상 판정. 로컬 리소스로 바꾸거나 그대로 두고 판단 |
| 최적화해도 점수가 그대로 | 남은 finding이 허용 목록으로 못 고치는 종류 | 정상. 무엇이 남았는지 finding으로 확인 |
| 크레딧 부족 | 초기 25 소진 | 데모 업그레이드(+100, 1회) 안내. 실제 결제 아님 |
| 3D 미리보기가 안 열림 | 미리보기 파서 한계 | 판정에는 영향 없음. 점수와 finding은 바이트에서 계산됩니다 |
