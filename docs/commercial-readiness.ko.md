# 상용 판매 준비도 — 감사 결과와 처리 현황

작성일: 2026-08-21. 기준: 보안·개인정보 감사 1건, 상용 완성도 감사 1건(실제 브라우저 조작으로 재현).

이 문서는 "Clunk를 지금 돈 받고 팔 수 있는가"에 대한 근거 목록이다. 해결한 것은 커밋과 검증
출력이 함께 있고, 남은 것은 왜 남았는지 적었다. **없는 진척을 적지 않는다.**

## 한 줄 판정

**아직 팔 수 없다.** 결제 코드가 존재하지 않고(`BillingProvider`는 구현체 0개인 빈 인터페이스),
자체 로그인이 없어 자체 도메인에서는 가입 자체가 불가능하다. 그 둘을 제외한 "팔면 사고 나는"
결함은 상당수 제거했다.

## 해결

| 심각도 | 결함 | 무엇이었나 | 조치 |
| --- | --- | --- | --- |
| 치명 | 헤더 사칭 | `oai-authenticated-user-id` 헤더를 무검증 신뢰. workspace id가 userId에서 파생되므로 헤더 한 줄로 남의 이력·Passport·크레딧 전체 접근 | 워커에서 신뢰 호스트 밖 요청의 신원 헤더 제거(fail-closed). `CLUNK_TRUSTED_AUTH_HOSTS` 필수 |
| 치명 | 무상 크레딧 지급 | `POST /api/credits {"action":"simulate-upgrade"}`가 결제 검증 없이 +100 | 사업자 정보가 채워져 `CAN_SELL`이 참이 되는 시점에 자동 차단 |
| 치명 | 쓰레기 파일 92점 | 텍스트를 `.glb`로 rename하면 92/100. 파싱 실패를 format 카테고리에서만 감점 | 읽지 못한 파일은 전 카테고리 0점·READY 아님. 회귀 테스트 고정 |
| 치명 | 오류 원인 은폐 | 실패 리포트의 byteLength가 항상 0이라 저장 API가 거부 → 원인 불문 `Invalid asset byte length.` 한 줄 | 실제 길이 사용. 진짜 진단이 서로 다르게 표출됨 |
| 중요 | 파서 DoS | 노드마다 같은 자식을 두 번 적은 900바이트 파일이 2^40회 방문 유발, 탭 영구 정지 | 메모이즈+반복문. 2000노드 폭발 케이스 3ms |
| 중요 | 임베드 폭탄 | base64 data URI를 바이트당 JS number로 누적, 문자마다 indexOf | 사전 크기 산정 + 조회 테이블 + 128MB 상한. 3MB 임베드 16.8ms |
| 중요 | 임베드 실패 은폐 | 디코드 실패한 임베드 리소스가 조용히 사라지고 에셋은 멀쩡해 보임 | unresolved로 보고 |
| 중요 | 보안 헤더 전무 | CSP·HSTS·X-Frame-Options·nosniff 등 0건 | 워커에서 일괄 주입. WASM 미리보기 호환 검증 완료 |
| 중요 | 요청당 DDL 18개 | 인증 요청마다 CREATE 16 + 시드 INSERT 2. 크레딧 미차감 엔드포인트로 쓰기 한도 소진 가능 | 아이솔레이트당 1회 캐시(실패 시 재시도) |
| 중요 | 삭제·내보내기 부재 | 개인정보처리방침이 약속한 파기·열람 권리를 이행할 코드가 0 | `GET/DELETE /api/account`, `GET /api/account/export`, 설정 화면 UI. A/B 격리 삭제 검증 완료 |
| 중요 | 데모 프록시 노출 | 0.0.0.0 바인딩 + 토큰 선택. 같은 네트워크의 누구나 로그인된 워크스페이스 열람 | 루프백 기본, 외부 노출은 옵트인 + 토큰 필수 |
| 판매차단 | 법정 고지 부재 | 이용약관·개인정보처리방침·환불정책·사업자 정보 전부 없음 | 3종 신설. 수집 항목표는 실제 D1 스키마에서 1:1로 작성 |
| 이탈 | 영어 오류 노출 | `Not enough demo credits.` 등. 인프라 설정 경로까지 화면에 노출 | 전면 한국어화 + 기계 판별용 `code` 필드. 내부 사정은 서버 콘솔로만 |
| 이탈 | 죽은 CTA·거짓 문구 | "출시 알림 받기"가 알림 수단 없는 문서로 이동. "실패하면 자동 복구" 약속은 호출부 0건 | 실제 접수되는 메일 링크로 교체, 문구는 실제 동작대로 |
| 이탈 | 지원 채널 부재 | 문의 폼·FAQ·상태·보안 신고 경로 전무 | `/support` 신설: 창구별 응답 목표, 현재 하지 못하는 일, FAQ |
| 이탈 | 표기 불일치 | 같은 문서에서 MCP 도구 4개와 6개가 공존. CLI 사용법도 4개만 나열 | 단일 소스(`MCP_TOOL_COUNT`)로 통일 |
| 이탈 | 랜딩 법적 링크 0 | 랜딩만 자체 푸터를 써서 법적 고지 링크가 없음 | 추가 |
| 이탈 | 공유 카드 파손 | `metadataBase` 미설정 시 localhost로 떨어져 OG 이미지가 뜨지 않음. og 크기 오선언 | 정정. robots·sitemap 신설 |

## 진행 중

- 검사기: 대용량 파일에서 탭 정지, 저장 실패 시 로컬 결과 소실, 크레딧 사전 검사·잔액 상시 표시
- 자체 로그인(GitHub OAuth) — 호스트 밖 가입 경로 확보

## 남은 것과 그 이유

| 항목 | 왜 남았나 |
| --- | --- |
| **결제 연동** | `BillingProvider`는 인터페이스만 있고 구현체가 없다. 청구서·영수증·결제수단·플랜 변경·해지 화면 전부 미구현. 실제 PG 계약과 사업자 등록은 운영자 본인만 할 수 있다 |
| **사업자 정보 기재** | 전자상거래법 제10조 표시의무. `app/legal/company.ts`를 채우면 전 페이지에 반영되고 `CAN_SELL`이 참이 된다. 현재는 사업자 등록 전이므로 비워 둔 것이 정확한 상태다 |
| **서버 재검증** | 검사가 이용자 기기에서 실행되므로 서버는 결과를 재검증하지 않는다. 즉 Passport는 발급자가 위조할 수 있다. 근본 해결(서버 재검사)은 별도 과제이며, 그 전까지 화면에 "같은 파일로 재현 대조는 가능하지만 제3자 감사 증명은 아니다"라고 명시했다 |
| **요청 속도 제한** | 아직 없다. Cloudflare rate limiting 또는 자체 구현이 필요하다 |
| **오류 알림 접근성** | 오류·알림 배너에 `aria-live`가 없어 스크린리더에 전달되지 않는다 |
| **손실 최적화** | 메시 단순화·텍스처 재인코딩(KTX2/Basis)·Draco·Meshopt 미지원. 용량 절감을 원하는 고객에게는 지금 맞지 않는다. `/support`에 명시했다 |

## 유료 전환 전 최소 순서

1. 검사기 안정성(진행 중)과 자체 로그인(진행 중) 완료
2. 사업자 등록 → `app/legal/company.ts` 기재 → `CAN_SELL` 참 전환 확인
3. 결제 연동(신규 개발) + 청구·해지 화면
4. `CLUNK_TRUSTED_AUTH_HOSTS` 배포 설정 확인
5. 서버 재검증 도입, 또는 Passport의 성격 표기를 최종 확정
