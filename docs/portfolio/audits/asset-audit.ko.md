## 0. 바이트 동일성 — 무엇을 봤는가

유료 상품이라 익명 다운로드는 401을 반환합니다.

```
curl -s -o /dev/null -w "%{http_code}\n" \
  "https://clunk.games/api/marketplace/assets/asset-w1-hf-player-farmhand?file=player-farmhand.m1.glb"
# -> 401  (AUTHENTICATION_REQUIRED, 유료 리스팅 + 로그인 없음)
```

그래서 **워커가 서빙하는 것과 같은 리포 내 원본**(`public/market/<slug>/<entryFileName>`)을 썼고,
30건 전부 API가 보고하는 `byteLength`와 로컬 파일 크기가 **정확히 일치**함을 확인했습니다(30/30 MATCH).
즉 여기 그림은 구매자가 받는 바이트에서 나온 것이 맞습니다. 다만 R2 객체 해시까지 대조하지는 못했습니다(인증 필요).

## 2. 카탈로그 전체를 관통하는 결함 5가지

1. **텍스처가 단 한 장도 없다.** 3D 15건 전부 `textureCount = 0`, UV 없는 메시가 15건 중 13건에서 전부(예: 트랙터 182/182, 파종기 410/410). 색은 정점 컬러 + 팔레트 머티리얼뿐. 그래서 어떤 각도에서도 표면이 "플라스틱 단색"으로 읽힙니다.
2. **상점에 표기된 삼각형 수가 실제 그려지는 수와 다르다.** 리스팅 값은 *고유 지오메트리* 합계이고, 씬에 배치하면 노드 인스턴스만큼 곱해집니다.
   파종기 10,880 → **51,602 (4.74배)**, 경운기 10,892 → 27,848 (2.56배), 가공라인 24,156 → 49,084 (2.03배), 트랙터 32,300 → 56,056 (1.74배).
3. **드로우콜이 게임용으로 못 쓸 수준.** 파종기 410 메시, 트랙터 182, 가공라인 142, 경운기 104. 텍스처 아틀라스가 없으니 배칭도 불가능합니다.
4. **애니메이션이 "있다"와 "보인다"가 다르다.** 농부 idle 8.976초 동안 최대 이동량 **27.9 mm**(사실상 정지), 경운기 work 1.627초는 8프레임이 육안으로 동일, 가공라인 run 8.296초는 142개 중 **15개**만 움직입니다.
5. **스케일이 서로 안 맞는다.** 농부 키 **2.4992 m**(모자 포함, 머리끝 2.2989 m) vs 마켓 스톨 높이 2.2563 m. 즉 자기 가게보다 큰 농부입니다. 빗물통(`hf-water-butt`)은 2.3255 m — 빗물통이 아니라 사일로 크기.

텍스처 8건 공통: **베이스 컬러 PNG 한 장뿐**입니다. 노멀·러프니스·AO 맵이 없어 3D에 그대로 쓰면 평평하게 보이고, 1024²에 장당 2.5–3.1 MB는 압축 포맷 대비 3배 이상입니다. 또 이 사진풍 텍스처와 같은 상점의 무텍스처 정점컬러 로우폴리 모델은 **서로 붙여 쓸 수 있는 아트 스타일이 아닙니다.**

## 4. 가장 나쁜 문제 5개 — 어느 그림 어디에 보이는가

1. **상점 뷰어가 농부의 뒤통수를 보여준다** — `hf-player-farmhand.png` 1행 1칸(front 3/4)에는 얼굴이 없고 1행 3칸(back 3/4)에 눈이 있습니다. 리포는 `outputs/market-launch/wave1/tools/assets.mjs`에 `viewDir: [0.78, 0.5, -0.92]`로 정면이 −Z임을 이미 알고 있는데, `app/components/AssetPreview.tsx`의 초기 카메라는 항상 `(+X, +Y, +Z)`입니다. 상품 페이지를 연 사람이 첫 화면에서 보는 건 밀짚모자 뒤통수입니다.
2. **트랙터 앞바퀴가 보닛을 뚫는다** — `hf-tractor-compact.png` 1행 2칸(side)의 앞바퀴 상단. 측정: `tread -> hood` 최소 표면거리 **0.0 mm**(24위상 전부).
3. **울타리 문 스윙 스프라이트의 살이 점선으로 부서진다** — `cozy-fence-gate-swing-sprites.png` 1행(swing_south) 2/8·3/8 프레임과 5행(swing_north) 전 프레임. 64 px 셀에서 대각 살이 서로 떨어진 픽셀 점으로 렌더됩니다. bbox 지터는 swing_west에서 27 px.
4. **가공라인에 6.6 × 3.8 m 초록 바닥판이 박혀 있다** — `hf-processing-line.png` 1행 4칸(top)에서 기계를 감싼 직사각형 판, 1행 1칸에서도 청록색 받침으로 보입니다. `processingFoundation`, 삼각형 528개, Y 0.109–0.289 m.
5. **나무 스프라이트가 64 px 셀에서 18 px 짜리 얼룩이다** — `grove-tree-pack-vol1-sprites.png` 하단 스트립 전체. 측정 bbox는 18×47(남향). 셀 가로의 72%가 빈 알파입니다.

## 5. 실패·한계 (숨기지 않음)

- **유료 리스팅의 실제 다운로드 바이트는 못 받았습니다**(401). 리포 사본과 API `byteLength`가 30/30 일치하는 것으로 동일성을 대신했습니다. R2 객체 해시 대조는 안 했습니다(D1/R2 접근 금지 지시).
- `tmp/audit-hf/mindist.mjs`는 ALLOW 목록 없이 돌리면 **의도된 접합부(허브·베어링·바퀴축)도 0 mm로 보고**합니다. 그래서 "0 mm = 결함"으로 읽지 않았고, 이름상 닿으면 안 되는 쌍만 뽑았습니다(풍차 날개↔탑 206.7 mm 정상, 트랙터 트레드↔보닛 0 mm 결함).
- `tmp/audit-clunk/coplanar.mjs`는 **InstancedMesh의 인스턴스 행렬을 반영하지 않습니다.** 트랙터의 SF 수치 대부분이 이 때문에 부풀려져 있으며 위 표에 그렇게 적었습니다.
- `scripts/dogfood-intersections.mjs`는 임의 경로가 아니라 자체 디렉터리 목록을 스캔하는 CLI라 이번 감사에서는 쓰지 않고, 대신 표면 최소거리(mindist)와 동일평면(coplanar) 두 축으로 대체했습니다.
- "발 미끄러짐"은 **제자리 걷기 사이클**이라 절대값만으로 결함 판정을 하지 않았습니다. 측정값: walk 0.827초 동안 발이 접지 상태에서 수평으로 **0.2361 m** 이동, 발 들림 0.0756 m, 최저점이 지면 아래 **−15.9 mm**까지 내려감. 보폭 0.236 m / 반주기 → 엔진이 루트를 약 0.57 m/s로 밀어줘야 미끄러지지 않습니다.
- 손-도구 거리는 노드 이름 필터에 `handle`이 걸려 `wateringCanHandle` 같은 손잡이가 도구 쪽 목록에서 빠졌습니다. 대신 몸통 기준으로 측정했습니다: water 클립에서 `rightHandMesh → wateringCanBody` **0.1217–0.1494 m**, hoe 클립에서 `leftHandMesh → 호미 자루(mesh_15)` **0.0244–0.1042 m**, harvest 클립에서 `rightHandMesh → harvestBasket` 0.2245 m. 전부 도구를 실제로 쥔 거리이며 **떠 있는 도구는 없었습니다.**
- 뒤집힌 면(inverted normal)은 15건 전부에서 **발견되지 않았습니다.** 각 시트 1행 6칸이 파일 그대로의 단면(FrontSide) 렌더인데, 1칸(상점이 강제하는 DoubleSide)과 실루엣 차이가 없습니다. 참고로 상점 뷰어는 `material.side = DoubleSide`를 강제하므로 만약 뒤집힌 면이 있었어도 상점에서는 안 보였을 것입니다.
- 농부의 퇴화 삼각형 204개는 파일에 실재합니다(면적 < 1e-12). 도구 메시들이 휴지 포즈에서 스케일 0으로 접혀 있는 것과는 별개 항목입니다.

## 6. 재현 명령 (전부 읽기 전용)

```bash
# 0) 라이브 카탈로그
curl -s https://clunk.games/api/marketplace -o tmp/asset-audit/data/marketplace.json

# 1) 정적 서버 (리포 루트를 그대로 서빙; three.js도 여기서 로드)
node tmp/asset-audit/tools/serve.mjs        # http://127.0.0.1:4321

# 2) 측정 — 삼각형/머티리얼/바운즈/클립/퇴화면/클립별 파트 바운즈
node tmp/asset-audit/tools/metrics.mjs public/market/<slug>/<file>.glb > tmp/asset-audit/data/<slug>.metrics.json

# 3) 모션 진폭 — 32위상에서 샘플 정점의 최대 이동(회전만 하는 부품도 잡힘)
node tmp/asset-audit/tools/motion.mjs  public/market/<slug>/<file>.glb > tmp/asset-audit/data/<slug>.motion.json

# 4) 동일평면 z-fighting (기존 도구)
node tmp/audit-clunk/coplanar.mjs public/market/<slug>/<file>.glb --json tmp/asset-audit/data/<slug>.coplanar.json

# 5) 움직이는 부품의 최소 표면거리, 24위상 (기존 도구)
PHASES=24 node tmp/audit-hf/mindist.mjs public/market/<slug>/<file>.glb tmp/asset-audit/data/<slug>.mindist.json <slug>

# 6) 컨택트 시트 — 헤드리스 Chrome + 실제 WebGL, 상품페이지와 같은 라이트 리그
node tmp/asset-audit/tools/run3d.mjs          # GLB 15건
node tmp/asset-audit/tools/run3d-pack.mjs     # 트리 팩 6개 파일 전부
node tmp/asset-audit/tools/run2d.mjs          # 스프라이트 7건 + 텍스처 7건
node tmp/asset-audit/tools/run2d-bundle.mjs   # 텍스처 번들 7장
```

렌더러 구성: Playwright 1.60 `channel: "chrome"`, `--use-angle=d3d11 --ignore-gpu-blocklist`,
three.js 0.179.1(리포 `node_modules`), 라이트는 `app/components/AssetPreview.tsx` 42–47행과 동일
(`HemisphereLight("#effcff","#10151e",2.4)` + `DirectionalLight("#9eeeff",3.2)` at (3,4,5), 배경 `#0b111a`, sRGB 출력).
각 칸은 640² 렌더를 320²로 다운샘플, 시트 폭은 2,560 px(3D) / 2,000 px 이상(2D).

## 7. 시트 읽는 법

**3D 시트 1행 8칸** — ①정면 3/4(상점 조명) ②측면 ③후면 3/4 ④상면 ⑤와이어프레임 ⑥단면 렌더(구멍이 보이면 면이 뒤집힌 것) ⑦노멀 방향 ⑧클레이(정점컬러 제거, 실루엣 판정).
**2행 이후** — 클립 하나당 한 줄, 클립 길이를 8등분한 시점. 캐릭터는 마지막 줄에 발·손 클로즈업 8칸.
**푸터** — 측정값. 주황색 줄은 게이트 위반.
**스프라이트 시트** — 위: 원본 시트(체커보드 = 알파). 아래: 4배 최근접 확대 스트립, 주황 사각형은 측정된 알파 bbox(칸마다 흔들리면 지터).
**텍스처 시트** — 왼쪽: 타일 1배. 가운데: 3×3 타일링, 주황선이 반복 이음매 위치. 오른쪽: 랩 차이 맵(밝을수록 급격한 경계).
