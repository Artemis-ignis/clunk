## 1. 무엇을 왜 만들었나

### 상황 (JTBD)

게임을 만드는 사람이 에셋을 구할 때 하는 일은 "3D 모델을 산다"가 아니라
**"내 게임에 넣어도 되는지 확인하고 싶다"** 입니다. 생성형 도구가 늘면서 에셋 공급은
넘치는데, 그 파일이 내 엔진에서 열리는지·얼마나 무거운지는 여전히 받아 보기 전에는
모릅니다.

- **변하지 않는 가치** — 내 게임에 넣어도 문제가 없어야 한다
- **변한 상황** — 만드는 비용이 0에 수렴해서 후보가 폭증했다. 그래서 **고르는 비용**이
  전체 비용이 되었다

밀크셰이크가 고용되는 이유가 "맛"이 아니라 "운전 중 한 손"이듯, 이 시장에서 고용되는
이유는 "예쁜 모델"이 아니라 **"확인된 모델"** 이라고 봤습니다.

### 문제 정의

> 파는 쪽도 자기가 파는 파일을 재지 않고 판다.

이건 가설이 아니라 제가 **제 가게에서 확인한 사실**입니다(4장).

### 그래서 만든 것

| 화면 | 하는 일 |

**차별점은 "파는 것"이 아니라 "재는 것"** 입니다. 상품 페이지의 모든 숫자는 파일에서 다시
재고, 어긋나면 검사가 배포를 막습니다.

## 2. AI를 어떻게 썼나 — 증강한 지점과, AI가 틀린 지점

강의의 다섯 칸(업무 문제 → AI에 맡긴 작업 → 발견한 오류·한계 → 수정한 판단 → 결과)으로
적습니다. **AI가 틀린 칸이 이 표에서 제일 중요합니다.**

### 2-1. 파는 에셋이 실제로 파는 대로인가

| | |
| --- | --- |
| **업무 문제** | 상품 22종이 설명대로인지 아무도 눈으로 본 적이 없다 |
| **AI에 맡긴 작업** | 22종을 여섯 각도로 렌더해 대조표 생성(`npm run asset:visual`), Opus 에이전트 4대가 병렬로 에셋 22종·사이트 13화면을 훑고 결함을 순위까지 매겨 보고 |
| **발견한 오류·한계** | ① 에이전트가 "부품 이름이 파일에 없다 → 없는 부품을 판다"고 단정. 실제로는 **포장 단계가 메시를 재질별로 합치면서 이름을 지운 것**이라, 물건은 있고 이름만 없었다 ② "도구가 크기 0이니 결함"이라고 봤는데, **여섯 동작 전부가 그 크기를 제어**하고 있었다 — 파일은 맞았다 |
| **수정한 판단** | 검사가 **단정하는 범위를 좁혔다.** 이제 확실한 것(이름이 있고, 어떤 동작도 크기를 안 건드리는데 크기가 0)만 결함으로 세고, 나머지는 "눈으로 확인할 것"으로 넘긴다. **없는 걸 있다고 하는 것보다, 있는 걸 없다고 하는 쪽이 더 나쁜 거짓말**이기 때문이다 |
| **결과** | 확정 결함 0건 / 눈으로 확인할 것 11건으로 정리. 그 과정에서 자동 감사가 통과시킨 진짜 결함들이 드러났다 — 트랙터 앞차축이 허브보다 **150mm 위**를 지나고 **17mm 모자라** 닿지도 않음, 게이지 휠 6개가 **102mm 부양**, 풍차 날개가 자기 탑을 **192mm 관통** |

### 2-2. 내가 쓴 상품 이름이 거짓이었다

| | |
| --- | --- |
| **업무 문제** | 상품 이름이 "농가·헛간·농부"라 카드에서 아무것도 구분되지 않았다 |
| **AI에 맡긴 작업** | 파일 안 노드 이름을 읽어 물건의 정체를 파악하고 이름 44개를 다시 지음 |
| **발견한 오류·한계** | 노드에 `toolWateringCan`, `toolHarvestBasket`, `toolHoe`가 있길래 **"도구 세 가지를 든 밀짚모자 농부"** 라고 지었다. 실물을 재지 않았다 — 쉬는 자세에서 셋 다 크기 0이라 카드에는 **빈손**으로 나온다 |
| **수정한 판단** | 이름은 노드가 아니라 **눈에 보이는 것**에서 지어야 한다. `동작마다 도구가 바뀌는 밀짚모자 농부`로 고쳤다 |
| **결과** | 같은 실수를 막는 검사를 만들었다 — 상품 글이 파는 부품이 파일에 있고 보이는지 대조(`npm run asset:claims`) |

### 2-3. 검사가 있는 줄 알았는데 안 돌고 있었다

| | |
| --- | --- |
| **업무 문제** | 운영자가 눈으로 결함을 찾아내는데, 검사는 전부 통과였다 |
| **AI에 맡긴 작업** | "왜 통과했는지" 밑바닥까지 추적 |
| **발견한 오류·한계** | **검사 파일 80개 중 18개가 어느 실행 스크립트에도 걸려 있지 않았다.** 이름이 `site-quality-contract`, `ui-readability-contract`, `public-journeys-contract` — 정확히 그 결함들을 잡으라고 쓴 검사가 조용히 낡아 있었다. 그중 하나는 **버그를 얼려 두고** 있었다(텍스처 검사용 프로필의 텍스처 예산이 0) |
| **수정한 판단** | 통과하는 14개는 즉시 연결하고, 실패하는 4개는 "검사가 낡은 것 / 제품이 망가진 것 / 기능이 사라진 것"으로 분류했다. **초록으로 만들려고 단언을 느슨하게 풀지 않았다** — 아무것도 검사하지 않아서 통과하는 검사는 없느니만 못하다 |
| **결과** | 검사 **399건 → 463건**, 안 도는 검사 **18 → 0** |

### 2-4. 구독자 전용이 무료로 나가고 있었다

| | |
| --- | --- |
| **업무 문제** | 운영자가 "구독자 전용이라고 써 놓고 무료 계정으로 받아진다"고 신고 |
| **AI에 맡긴 작업** | 문지기 코드와 구독 데이터 추적 |
| **발견한 오류·한계** | 문지기에는 구멍이 없었다. **무료 베타에서 "받기"를 누르면 그 에셋에 영구 소유 기록이 발급**되고, 문지기가 그것을 "값을 치른 사람"으로 읽고 있었다 |
| **수정한 판단** | 베타 기록은 **베타 중에만** 인정하도록 좁혔다. 실제로 값을 치른 기록은 판매가 열린 뒤에도 그대로 인정한다 — 받은 것을 거두지는 않는다 |
| **결과** | 구독을 여는 날 베타 사용자 전원이 유료 에셋을 영구 무료로 갖게 되는 상황을 막았다. 회귀 방지 검사 추가 |

## 3. 품질을 어떻게 정의했나 — Eval 네 층

"잘 작동한다"를 **측정 가능한 문장**으로 바꾸는 것이 이 제품의 핵심입니다.

| 층 | 묻는 것 | 이 저장소에서 |
| --- | --- | --- |
| **문제 Eval** | 중요한 문제인가 | 팔던 30건을 전수 감사 → **8건은 내려야 한다**는 결론. 문제가 실재함을 내 물건으로 증명 |
| **산출물 Eval** | 요구를 지켰나 | 검사 463건. 상품 페이지의 폴리곤·크기·요구 확장이 **파일에서 다시 잰 값과 다르면 배포가 막힘** |
| **제품 경험 Eval** | 사용자가 성공했나 | 21개 화면 문구 훑기, 22종 6각도 렌더 대조표, 대비비 실측 |
| **사업 Eval** | 지속 가능한가 | Cloudflare 무료 구간 · 쓴 돈은 도메인뿐. 다만 **매출 0** — 아래 5장 |

모호한 기준을 평가 가능한 기준으로 바꾼 예:

| 모호함 | 이 저장소가 쓰는 기준 |
| --- | --- |
| "색이 잘 나온다" | 정점 색을 그림으로 옮긴 뒤 꼭짓점마다 대조, **최대 오차 0.50 sRGB 칸**(8비트 반올림 한계) |
| "글씨가 잘 보인다" | 히어로 PNG 30장에서 칩이 앉는 띠를 픽셀째 읽어 WCAG 대비 **9.76:1 / 8.24:1**(고치기 전 1.21:1) |
| "부품이 잘 붙어 있다" | 부품 쌍마다 광선을 쏘아 관통 깊이 mm 로 판정 + 48위상 회전 전수 검사 |

## 4. 팔던 물건을 내린 이야기

가장 자신 있는 대목이라 따로 씁니다.

라이브에서 팔고 있던 **30건 전부**를 렌더링·측정해 판정했습니다.

- **그대로 판매 가능 6건 / 수정 16건 / 내려야 함 8건**
- 표기 폴리곤이 실측과 **최대 4.74배** 차이(파종기 10,880 → 51,602)
- 사이트·문서의 주장 **102개**를 코드·API와 1:1 대조 → **틀림 22 · 과장 10**

원본: [에셋 감사](audits/asset-audit.ko.md) · [문구 감사](audits/copy-audit.ko.md)

**이게 제가 일하는 방식입니다.** 기능을 더 붙이는 대신, 이미 내놓은 것이 사실인지 먼저
재고, 아니면 내리거나 고칩니다. 그리고 그 판정을 문서로 남겨 남이 재현할 수 있게 합니다.

## 5. 이 프로젝트가 증명하지 못하는 것

강의가 말한 대로, **돈 안 내는 사용자는 End User이지 고객이 아닙니다.**

- **매출 0원.** 결제 기능을 의도적으로 잠가 뒀습니다(전자상거래법상 청약철회 고지·동의
  절차와 사업자 요건을 갖추기 전에 팔지 않기로 한 결정)
- **사용자 수·재방문율 없음.** 측정하지 않았거나 내세울 수준이 아닙니다
- 그래서 이 포트폴리오는 "팔아서 얼마를 벌었다"를 주장하지 않습니다. 주장하는 것은
  **"팔 수 있는 상태인지 재고, 아니면 내렸다"** 입니다

## 6. 나에 대해

- **책임은 위임하지 않습니다.** 이 저장소에서 AI가 쓴 코드의 비중은 큽니다. 그런데 배포를
  누를지, 무엇을 내릴지, 어떤 문장을 지울지는 전부 제가 정했고, 틀렸을 때 되돌린 기록도
  커밋에 남아 있습니다(예: 2-2의 이름 오기 — 파일을 고쳤다가 **제가 틀렸음을 확인하고
  파일을 되돌린 뒤 제 문구를 고쳤습니다**)
- **재기 전에는 말하지 않습니다.** 이 문서의 숫자는 전부 재현 명령이 있습니다
  ([부록 A](clunk.ko.md#부록-a-이-문서의-숫자를-직접-확인하는-법))
- **불리한 것을 먼저 씁니다.** 매출 0, 내려야 할 상품 8건, 안 돌고 있던 검사 18개 —
  전부 제가 찾아 제가 적었습니다
