# 모두의 창업 프로젝트 2차 일반·기술트랙 1차 서면심사(1R) 패널 리뷰

## 심사 전제

- 심사 대상: `docs/application/form-answers.ko.md`의 Q1, Q2, Q3-1, Q3-2, Q4-1, Q4-2, Q8, Q10
- 심사 기준: 차별성·효과성
- 평가 방식: 책임멘토 3인의 독립 관점에서 10점 만점 주관 평가
- 사실성 원칙: 신청서에 적힌 구현·검증 사실과 계획을 구분했다. 확보하지 않은 고객·매출·성능·지불의사는 성과로 인정하지 않았다.

## 2. 30초 훑어읽기 첫인상과 탈락 위험

### 첫인상

“문제를 실제로 겪은 개발자가 GLB/GLTF를 파일 바이트 기준으로 검사하고, 원본을 보존한 채 최적화 후 재검사·증적화하는 MVP를 만든 팀”이라는 인상이 먼저 온다. 특히 포맷 유효성 검사와 게임 투입 품질 검사를 구분하고, 결과를 해시와 Passport로 남긴다는 점은 기술 차별성으로 읽힌다.

동시에 “실제 사용자는 아직 창업자 본인과 자체 런타임 샘플 중심이며, 고객이 돈을 낼 이유와 효과는 이제 검증하려는 단계”라는 인상도 강하다. 기술 설명의 밀도가 높아 30초 안에는 제품의 작동성은 보이지만, 시장의 긴급성과 구매자의 손실은 선명하게 남지 않는다.

### 탈락 위험 요소

1. 고객 인터뷰, 반복 사용, 유료 고객, 매출, 지불의사 데이터가 없다. 신청서가 이를 정직하게 밝힌 것은 장점이지만, 효과성 심사에서는 감점 근거가 된다.
2. 초기 고객 후보가 인디·소규모 게임팀, 외주 통합팀, 생성형 3D 도구 사용자, 마켓 판매자로 넓게 퍼져 있다. 누가 첫 구매자인지 한 번에 잡히지 않는다.
3. “검사 통과 증명”과 “보안 부담을 구조적으로 줄인다”는 문장이 구매 효과를 이미 입증한 것처럼 읽힐 수 있다. 현재 확보한 것은 기능과 특정 샘플 검증이지 사업 효과 측정이 아니다.
4. Q4-1의 `파일럿 10팀 내외`, `첫 유료 워크스페이스`는 계획 수치인데, 모집 접점이나 전환 근거가 함께 제시되지 않는다.
5. Q8의 `[마스터 확인]` 미완성 표식은 심사자가 “신청자 역량 서술이 아직 제출본이 아니다”라고 판단하게 만들 수 있다. 실제 이력이 없으면 추가하지 말고, 표식만 남긴 채 제출하지 않아야 한다.
6. Q10의 “게임에 바로 넣어도”와 “안전하게 고친 뒤”는 프로젝트별 엔진·정책 검증이 필요한 제품의 실제 경계보다 넓은 보장으로 읽힐 수 있다.
7. Q3-1·Q8의 기술 용어와 자동 테스트 서술이 많아, 비기술 심사자에게 차별성은 전달돼도 효과성은 “그래서 시간·비용·실패를 얼마나 줄이는가”로 연결되지 않을 수 있다.

## 3. 우선순위별 구체적 개선 제안

아래 제안은 확보하지 않은 성과를 새로 쓰지 않는 조건으로 분류했다.

1. **Q8의 `[마스터 확인]`을 제출 전 반드시 실제 본인 사실로 완결하거나, 사실이 없으면 해당 성과를 추가하지 않고 문단을 삭제한다.**
   - 판정: **새로운 성과 주장이 필요해서 반영 불가(날조 위험)**
   - 이유: 학력·경력·수상·활동은 신청자에게 확인받기 전에는 작성할 수 없다. 이는 문장 개선 문제가 아니라 사실 입력 문제다.

2. **첫 고객 후보를 하나의 우선순위로 좁힌다.** 예: “외주·마켓 에셋을 반복 통합하는 인디·소규모 게임 개발팀”을 1차 대상으로 두고, 생성형 3D 도구 회사·마켓 검수 연동은 후순위 가설로 이동한다.
   - 판정: **검증된 사실만으로 반영 가능**
   - 이유: 새 고객이나 성과를 주장하지 않고, 현재 신청서에 이미 적힌 후보군의 순서를 정리하는 작업이다.

3. **Q3-1의 차별점을 `실제 바이트 기반 측정 → 허용 목록 최적화 → 출력 파일 재검사·Passport` 세 축으로 먼저 요약하고, CLI·MCP·VS Code 확장은 뒤로 보낸다.**
   - 판정: **검증된 사실만으로 반영 가능**
   - 이유: 신청서에 이미 서술된 구현과 검증 사실의 배열을 바꾸는 편집이다.

4. **Q2와 Q3-1에서 “많은 팀에게 필요하다”, “보안 부담을 구조적으로 줄였다”처럼 외부 효과로 읽히는 문장을, 현재 확보한 범위인 “창업자의 실제 개발에서 확인한 문제”와 “원본 바이트를 자동 업로드하지 않는 현재 구조”로 제한한다.**
   - 판정: **검증된 사실만으로 반영 가능**
   - 이유: 시장 규모나 보안 효과를 새로 주장하지 않고, 이미 적힌 관찰·제품 구조만 정확하게 표현한다.

5. **Q3-2에서 구독·크레딧·Passport 단가를 확정된 수익모델이 아니라 검증할 가격 가설로 명시하고, 현재 사실인 “결제는 데모이며 매출·유료 고객은 없음”을 짧고 앞쪽에 배치한다.**
   - 판정: **검증된 사실만으로 반영 가능**
   - 이유: 가격을 새로 만들거나 지불의사를 주장하지 않고, 신청서가 이미 인정한 현재 단계를 선명하게 한다.

6. **Q4-1의 단계별 목표를 기능 확장 목록보다 검증 질문 중심으로 다시 쓴다.** “반복 사용되는가 → 어떤 단위에 지불 의사가 있는가 → 어떤 정책·엔진 요구가 실제로 반복되는가” 순으로 두고, 10팀과 첫 유료 워크스페이스는 목표 또는 가설임을 명시한다.
   - 판정: **검증된 사실만으로 반영 가능**
   - 이유: 새로운 파일럿 결과를 쓰는 것이 아니라 기존 계획의 성격과 순서를 명확히 하는 편집이다.

7. **Q4-2의 멘토 요청을 첫 고객 발굴과 가격 인터뷰 설계라는 두 가지 우선 과제로 압축하고, 매 회차 가져올 데이터는 “향후 측정할 데이터”라고 표시한다.**
   - 판정: **검증된 사실만으로 반영 가능**
   - 이유: 멘토링 요구와 측정 계획은 이미 답변에 있으며, 실제 데이터를 확보했다고 주장하지 않는다.

8. **Q10의 보장처럼 읽힐 수 있는 표현을 “게임 투입 전 파일을 검사하고, 허용된 정리와 재검사 증거를 남기는 품질 검사소”처럼 현재 기능 범위로 조정한다.**
   - 판정: **검증된 사실만으로 반영 가능**
   - 이유: 성능 향상이나 호환성 보장을 추가하지 않고, 실제 구현 범위를 더 정확히 표현한다.

9. **효과성 문장을 수치 성과 대신 의사결정 단위로 구체화한다.** 예: “이 파일을 왜 통과시켰는지 입력·출력 해시, 정책 버전, finding, 전후 메트릭으로 다시 확인하게 한다.” 고객이 절약한 시간·비용을 주장하지 말고 제품이 제공하는 증거 단위만 쓴다.
   - 판정: **검증된 사실만으로 반영 가능**
   - 이유: 이미 답변에 있는 Passport 구성요소를 효과의 메커니즘으로 연결하는 작업이다.

10. **“10팀 모집”, “첫 유료 워크스페이스”, “6~12개월 엔진별 프로파일·제휴”를 실제 접점·일정·자원 근거가 없는 확정 성과처럼 보이지 않게 `목표`, `검증 가설`, `조건부 확장`으로 표기한다. 근거가 없으면 목표 수치를 삭제한다.**
    - 판정: **새로운 성과 주장이 필요해서 반영 불가(날조 위험)**
    - 이유: 수치를 유지하려면 실제 모집 접점이나 전환 근거를 새로 확보해야 한다. 그 근거가 없을 때 숫자를 더 그럴듯하게 만드는 것은 권하지 않는다.

## 4. 종합 판정

### 판정: 조건부 통과 가능 수준이나, 현재 초안 그대로는 안정적인 1R 통과권으로 보기 어렵다.

기술 차별성만 보면 통과 경쟁력이 있다. 단순 포맷 검사나 변환 도구가 아니라, 실제 GLB/GLTF 바이트에서 정책 기반 finding과 score를 계산하고, 원본을 보존한 새 파일을 만든 뒤 다시 파싱·검사하고, 전후 hash와 규칙 정보를 Passport로 남긴다는 흐름이 구체적이다. 특정 런타임 GLB 8개를 읽기 전용으로 검사했다는 사실과 결제·고객 성과를 아직 만들지 않았다고 밝힌 점도 과장 억제 측면에서 긍정적이다.

그러나 1R의 다른 축인 효과성은 아직 제품 내부 효용의 설명에 머문다. 고객이 실제로 반복 사용했는지, 수동 검수보다 무엇이 얼마나 나아졌는지, 누가 어떤 단위로 돈을 낼지는 검증 전이다. 따라서 시장 회의론자에게는 “기술적으로 잘 만든 문제 해결형 MVP이지만 사업 효과의 증거가 없는 단계”로 분류될 가능성이 있다.

제출 전 최소 보완선은 세 가지다. 첫째, Q8의 미완성 표식을 실제 사실로 정리한다. 둘째, 첫 고객 후보와 검증 질문을 하나의 흐름으로 좁힌다. 셋째, `안전`, `바로 투입`, `영업 자료가 된다`처럼 효과를 앞서 확정하는 표현을 현재 확인된 기능·증거와 향후 가설로 분리한다. 이 세 가지를 반영하면 새 성과를 날조하지 않고도 서면 완성도와 차별성 전달력은 높아진다. 반대로 고객·매출·성능 수치를 새로 만들어 보강하는 것은 필요하지도, 권하지도 않는다.
